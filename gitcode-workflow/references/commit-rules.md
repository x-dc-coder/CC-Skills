# Git 团队协作提交规范

为了保持团队代码提交历史的清晰、可读，并便于自动化生成 Changelog 和追踪问题，本规范基于业内通用的 Conventional Commits 标准制定。

## 1. 提交格式

每次 Git 提交的说明（Commit Message）必须符合以下格式：

```
<类型>(<作用域>): <简短描述>
```

> **注意：** 冒号后面必须有一个英文空格。

## 2. 类型 (Type) 详解

类型用于说明本次提交的目的和性质。

| 类型           | 英文全称      | 详细说明与应用场景                                           |
| -------------- | ------------- | ------------------------------------------------------------ |
| **`feat`**     | Feature       | **新增功能**。当为系统引入全新的业务逻辑、界面元素、API 接口或功能模块时使用。这通常意味着产品功能的实质性增加。 |
| **`fix`**      | Bug Fix       | **修复缺陷**。当修复线上环境、测试阶段发现的代码错误、逻辑异常、崩溃问题或 UI 错位时使用。 |
| **`docs`**     | Documentation | **文档更新**。仅涉及 README、Wiki、代码注释、API 接口文档的变更，**不包含**任何生产代码的修改。 |
| **`style`**    | Style         | **代码格式调整**。不影响代码运行逻辑的纯格式修改，例如：调整缩进、处理末尾空格、统一引号、修正拼写错误、删除多余的空行等。 |
| **`refactor`** | Refactoring   | **代码重构**。对既有代码结构的调整，**既不是修复 bug，也不是添加新功能**。旨在提高代码的可读性、可维护性、优化算法实现或调整目录结构。 |
| **`perf`**     | Performance   | **性能优化**。专门用于提升程序运行速度、降低内存/CPU占用、优化数据库查询等性能相关的代码修改。 |
| **`test`**     | Test          | **测试相关**。新增缺失的测试用例，或修改现有的单元测试、集成测试、E2E测试代码，不涉及生产代码的变更。 |
| **`chore`**    | Chore         | **日常事务与构建配置**。构建过程（如 Webpack/Vite 配置）、辅助工具、依赖包管理（如 npm/Maven 包的升级、降级或移除）的更新或日常维护。 |
| **`revert`**   | Revert        | **代码回滚**。用于撤销之前的某次提交。描述中通常需要包含被撤销提交的 Hash 值。 |

## 3. 作用域 (Scope) 说明

作用域 `()` 是**强烈建议提供**的部分，用于说明本次提交影响的具体范围或模块。

作用域的命名应该尽量简短、清晰，通常对应于项目中的：

- **业务模块**：如 `user`, `order`, `payment`, `auth` 等。
- **技术组件**：如 `router`, `store`, `upload`, `utils` 等。
- **特定页面或分层**：如 `login-page`, `database`, `api` 等。

*特殊情况：如果某次重构或修改涉及全局或多个模块，可以使用 `global`、`core` 或直接省略作用域。*

## 4. 简短描述 (Subject) 规范

简短描述是对本次改动的精炼总结，需要遵循以下规则：

- **语言**：团队统一使用中文（特殊专业术语可保留英文）。
- **时态/语态**：使用祈使句/动宾结构，例如使用“新增...”、“修复...”、“优化...”开头。
- **大小写**：如果是英文字母开头，首字母小写。
- **标点**：结尾**绝不**添加句号（`.` 或 `。`）等标点符号。
- **长度**：简洁明了，总长度建议不超过 50 个字符。

## 5. 完整示例参考

**新增功能：**

```
feat(auth): 新增微信扫码登录逻辑
feat(user-profile): 增加用户头像上传限制
```

**修复 Bug：**

```
fix(payment): 修复并发支付时可能导致订单状态重复更新的问题
fix(router): 解决未登录用户可以直接访问后台页面的漏洞 (#123)
```

*(注：结尾的 `#123` 是关联 Issue 的最佳实践，方便追踪)*

**重构与优化：**

```
refactor(order): 抽取订单状态机判定逻辑到独立服务中
perf(image-list): 优化长列表图片的懒加载机制，减少内存占用
```

**依赖升级与日常维护：**

```
chore(deps): 升级 Vue 框架及相关依赖到 v3.4
chore(ci): 调整 GitHub Actions 的自动化部署脚本
```

**文档与测试：**

```
docs(api): 更新支付模块的回调接口说明
test(utils): 补充日期格式化工具类的单元测试
```
