# 论文级复杂图 Prompt 模板（架构图 / 模型结构图 / 机制传导图）

> 依据：next-ai-draw-io 主应用 system-prompts（410 行质量规则）+ MCP server 实测验证（Transformer 架构图：21 顶点[19 形状+2 容器]+16 边，端到端全通，导出 3048×2888 高清 PNG）。
> 用途：在客户端（Claude Code / Cursor / DSH / 任意 MCP 客户端）直接使用，可复制精调。

---

## 〇、总则：复杂图的本质要求

论文级图 ≠ 堆节点。判断标准：
1. **语义完整**：论文读者不看正文也能读懂结构（组件、流向、层级、输入输出齐全）
2. **布局有理**：流向单一（左右或上下）、分区清晰、层级用容器表达
3. **样式学术**：色板克制（≤5 色）、字体统一、线型区分（实线=数据流 / 虚线=控制流或跨模块）
4. **无视觉缺陷**：无重叠、无穿线、无越界（必须过 check-quality.py）
5. **可编辑可导出**：生成 .drawio（可改）→ 导出高清 PNG（论文插图）+ SVG（矢量备用）

## 一、通用六段式模板（推荐结构）

将下面模板整体粘贴给客户端，替换 [占位符]：

```text
请绘制一张论文级【[图表类型]】。要求如下：

【1. 角色与标准】
你是论文插图设计师，输出必须符合学术出版标准（IEEE/ACM 排版可用），
可直接作为论文中的 Figure 使用。

【2. 内容要素】（必须全部体现）
- 组件：[列出所有组件/模块/层，含中英文名]
- 连接：[列出关键连接关系：数据流、控制流、依赖、反馈]
- 层级/分组：[列出容器分组，如 Encoder Block、微服务边界、分层架构]
- 关键标注：[需要突出的数字、维度、协议、接口名]

【3. 布局规格】
- 流向：[从左到右 / 从上到下 / 混合（说明主流向）]
- 分区：[建议的列/行布局，如"左编码器右解码器"、"上中下三层架构"]
- 视口：850×1100（与 check-quality.py 默认一致）；推荐元素范围 x∈[40,800]、y∈[40,980]；容器最大 700×550；超大图用 --viewport 自定义质检视口或拆多页
- 间距：同层节点间距 150-200px，为连线留通道

【4. 样式规格】
- 色板：学术色板——主体蓝 #dae8fc/#6c8ebf、处理绿 #d5e8d4/#82b366、
  资源橙 #ffe6cc/#d79b00、异常红 #f8cecc/#b85450、外部紫 #e1d5e7/#9673a6
- 形状：处理用圆角矩形（rounded=1）、判断用菱形（rhombus）、起止用椭圆
- 线型：数据流实线 endArrow=classic；控制流/跨模块虚线 dashed=1
- 文字：fontSize≥12，标题 14 粗体，whiteSpace=wrap

【5. 边路由硬规则】（7 条，缺一不可）
1) 多边不共路：同对节点多条边用不同 exitY/entryY（0.3 与 0.7）
2) 双向边对侧进出：A→B 右出左进，B→A 左出右进
3) 每条边显式写 exitX/exitY/entryX/entryY 四属性
4) 绕障：连线路径上有中间形状必须加 waypoint（净空 20-30px）
5) 先规划再生成：按流向往分区，逐条边预演障碍
6) 复杂绕行用 2-3 个 waypoint 形成 L/U 形正交路径
7) 自然连接点：上下流底出顶进，左右流右出左进，禁角落连接

【6. 交付要求】
- 生成完整可编辑 .drawio 文件
- 导出高清 PNG（论文 300DPI：scale=4，宽≥2000px）和 SVG
- 全部元素过布局质检（无重叠/越界/孤立边）
```

## 二、三类图专项模板

### A. 系统/软件架构图（分层架构 / 微服务 / 云架构）

**要点**：容器表达边界（泳道/大矩形），跨边界连线必须绕行；云图标查形状库（aws4/azure2/gcp2/kubernetes，31 库全在 docs/shape-libraries/）。

```text
绘制[系统名]的[分层/微服务/云]架构图（论文级）。
层级（从上到下）：[用户层 → 接入层 → 应用层 → 服务层 → 数据层 → 基础设施]，
用透明容器大矩形表达每层边界（fillColor=none），层内节点 parent=容器。
跨层连线用正交边+waypoint 绕行，禁止穿越同层其他节点。
数据存储用圆柱形（shape=cylinder3），API 网关用特殊标记，外部系统用紫色虚线框。
[若需云图标]：先调用 get_shape_library 查询 aws4/azure2/gcp2/kubernetes 语法，
禁止猜测图标语法。图标尺寸 50×50，容器内相对坐标。
```

**精调**：
- 泳道图（多参与方流程）：把"层"换成参与者泳道，节点 parent=泳道 id
- 高并发/性能标注：节点下方加 text 子节点标注 QPS/延迟
- 部署架构：加 Nginx/K8s Pod/Service 等标准组件，图标库必须查

### B. 深度学习模型结构图（Transformer / CNN / RNN / 混合模型）

**要点**：块结构用容器（虚线框=重复块 ×N），特征图用矩形+维度标注，残差用跨层弯曲连线。

```text
绘制[模型名]的完整结构图（论文级，参考原论文 Figure 风格）。
布局：[按编码器-解码器/主干-分支/串行堆叠组织]，主流向[左到右/上到下]。
- 每个模块用圆角矩形，颜色按功能：[嵌入/输入蓝、注意力/卷积绿、归一化橙、线性/输出紫]
- 重复堆叠块用虚线容器框住并标注 "Block × N"
- 特征图/张量标注维度（如 [B, L, 512]）作为节点内第二行文字
- 残差连接/跨模块连接用虚线边，绕行加 waypoint
- 输入输出端明确：输入 Embedding、输出 Softmax/分类头
- 所有边显式 exitX/exitY/entryX/entryY，同对节点多边错开 exitY
```

**精调**：
- CNN：卷积层画特征图序列（宽高递减+通道递增），池化用特殊形状
- 注意力：多头用并行分支再拼接（concat 节点），mask 标注
- 训练流程图（loss/优化器）：流程节点+判断节点（收敛？）
- 图表尺寸超视口：压缩间距或拆两页（add_page），每页一个主题

### C. 机制传导图（数据流转 / 方法流程 / 信号传导）

**要点**：时序与因果是关键，边标注（数据/条件/信号名），分支判断明确。

```text
绘制[机制名]的传导/流转图（论文级）。
主流向：[从上到下表示时间/因果顺序]，用[阶段容器]分组。
- 每个环节用圆角矩形，标注[处理名+关键参数]
- 传导边标注[数据/信号/条件名]，实线=主路径，虚线=旁路/反馈
- 判断节点（条件分支）用菱形，分支标注 是/否
- 反馈回路用绕边（外围 waypoint）回到上游，禁止穿线
- 起止明确：起点椭圆"开始/输入"，终点椭圆"结束/输出"
```

**精调**：
- 数据流图：重点标注数据形态变化（原始→清洗→特征→预测）
- 时序图替代方案：如果主要是消息交互，用 sequenceDiagram（diagram-sequence skill）
- 状态机：状态用圆角矩形，转移边标注事件/条件

## 三、精调速查表

| 需求 | 调整方式 |
|---|---|
| 图太复杂（超视口） | 减小间距到 80-100px、缩小节点（120×40→100×36）、拆多页；质检用 --viewport 1200 800 匹配实际画布 |
| 黑白打印（期刊黑白版） | minimal 模式：去 fillColor，仅描边+灰度 |
| 加云图标 | get_shape_library 查库后引用 mxgraph.aws4.xxx |
| 中文 vs 英文标注 | 按论文语言统一；中英混排用 &lt;br&gt; 换行 |
| 强调某条边 | 加粗 strokeWidth=2、异色（如红色）、curved=1 |
| 层级更多 | 嵌套容器（父容器内再放子容器），注意容器透明 fillColor=none |
| 导出更清晰 | DRAWIO_EXPORT_SCALE=4（300DPI）；SVG 无损放大 |
| 多次修改 | 每轮 get_diagram → edit_diagram（按 id 精修），大改 create_new_diagram |

## 四、客户端（Claude Code / Cursor）接入配置

```json
{
  "mcpServers": {
    "drawio": {
      "command": "npx",
      "args": ["@next-ai-drawio/mcp-server@latest"],
      "env": { "DRAWIO_EXPORT_SCALE": "4" }
    }
  }
}
```

Claude Code CLI：
```bash
claude mcp add drawio -- npx @next-ai-drawio/mcp-server@latest
# 高清导出：export DRAWIO_EXPORT_SCALE=4 后启动客户端
```

**无头/服务器环境（无浏览器）**：WSL 无 DISPLAY 时 start_session 的 open 会失败，
设置 `BROWSER=echo` 跳过；渲染用 Playwright/Chromium 打开 `http://localhost:6002?mcp=<sessionId>`
充当浏览器（本方案已实测验证），或用 xvfb-run。
