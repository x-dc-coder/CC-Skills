# 论文引用与术语一致性修正

## 核心问题

处理长论文（通常 200KB+，数万字）时，上下文窗口限制导致无法一次性加载全文。
这会带来两个严重问题：

1. **引用编号混乱**：处理第 5 章时，已忘记第 2 章用了哪些编号，导致新增引用编号跳跃、重复，或与文末参考文献列表不对应。
2. **术语不一致**：同一概念在论文不同位置用了不同表述（如"虚拟社区感"vs"社区归属感"），但由于上下文截断，无法发现这种不一致。

本 skill 使用**外部状态文件法**解决：将关键信息持久化到文件中，逐章处理，确保全局一致性。

## 工作流程

### 阶段一：预分析（不占用上下文）

使用 Bash 工具快速分析论文结构，确定章节边界。这步只输出结构信息，不读取内容。

```bash
# 如果是单文件
wc -l <论文文件>                        # 总行数
grep -n '^# ' <论文文件>               # 一级标题位置
grep -n '^## 参考文献\|^# 参考文献' <论文文件>  # 参考文献位置

# 统计引用格式
grep -oP '\[\d+\]' <论文文件> | sort -n | uniq -c  # 所有 [数字] 引用
```

**输入判断：**
- 用户可能提供一个完整文件（如 `论文初稿_完整版.md`）
- 也可能提供分章节文件（如 `chapter1.md`, `chapter2.md`...）
- 如果是后者，按文件名排序处理

### 阶段二：第一轮扫描（生成状态文件）

创建 `_state/` 目录（与论文文件同目录），包含三个状态文件：

#### 状态文件 1: `_state/reference_index.md`

记录每个引用的完整信息，按首次出现顺序排列：

```markdown
# 参考文献索引

## [1] 首次出现: 第1章第1节
- 原始编号: [1]
- 新编号: [1]（待第二轮确定）
- 文献信息: AJZEN I. The theory of planned behavior[J]...
- 所在位置: 第1975行

## [2] 首次出现: 第1章第1节
...
```

**扫描规则：**
- 逐章读取论文内容（每次 Read 只读一章，约 500-1000 行）
- 按阅读顺序（从前到后）遇到每个 `[数字]` 引用时，记录到索引
- 同时记录文末参考文献列表中对应的完整文献信息
- 如果发现编号不连续（如正文中出现 [3] 但没出现 [2]），标记为"待修正"
- 如果发现编号重复（同一数字出现多次），标记为"重复引用"

#### 状态文件 2: `_state/term_glossary.md`

记录论文中的关键术语及其所有变体：

```markdown
# 术语一致性表

## 体育虚拟社区
- 推荐写法: 体育虚拟社区
- 首次出现: 第1章第1节
- 发现变体:
  - 虚拟体育社区（第3章第2节）→ 建议统一
  - 体育线上社区（第5章第1节）→ 建议统一

## 持续运动行为
- 推荐写法: 持续运动行为
- 首次出现: 摘要
- 发现变体:
  - 持续性运动行为（第2章）→ 建议统一
```

**术语识别规则：**
1. 摘要中出现的关键名词短语（通常是研究的核心变量）
2. 各章节标题中的术语
3. 文中**加粗**或*斜体*强调的概念
4. 在"概念界定"章节明确定义的术语
5. 出现频率高（>5 次）的专业短语（2-6 个字）

**变体检测规则：**
- 同一语义，字数差异在 ±2 字以内
- 常见替换："的"字有无（如"社区感"vs"社区的感"）、近义词替换（如"影响"vs"作用"）、顺序调换
- 英译不一致（如"Flow"vs"心流"vs"福流"）

#### 状态文件 3: `_state/changes_log.md`

记录扫描和修正过程中的所有发现：

```markdown
# 修改日志

## 扫描阶段发现
- [问题] 第3章出现 [15]，但 [14] 首次出现在第5章 → 编号顺序错误
- [问题] 第2章用"社群经济"，第6章用"社区经济" → 术语不一致

## 修正阶段记录
- [修正] 第5章 [14] → [12]，调整后续编号
- [统一] 第6章"社区经济" → "社群经济"
```

### 阶段三：全局检查（基于状态文件）

读取 `_state/reference_index.md`，执行以下检查：

**引用编号检查：**
1. **连续性**：正文中的引用编号是否从 [1] 开始严格连续？如有跳跃，标记待修正
2. **顺序性**：编号是否按首次出现顺序递增？如 [15] 比 [14] 先出现，标记待修正
3. **唯一性**：每个编号是否只出现一次？如有重复，标记待修正
4. **对应性**：正文引用的数量是否与文末参考文献列表条目数一致？
5. **尾注对应**：文末 [1] 的文献信息是否与正文中 [1] 第一次出现时描述的文献一致？

**术语一致性检查：**
1. 读取 `_state/term_glossary.md`
2. 对每条术语，检查其"发现变体"列表
3. 判断变体是否为真正的错误（有些变体是有意区分，如"工具型平台"vs"社群型平台"）
4. 生成"修正计划"写入 `_state/changes_log.md`

### 阶段四：执行修正（逐章修改）

基于 `_state/` 中的分析结果，逐章修正：

**引用修正策略：**
- 如果正文中引用编号不连续或顺序错误，**按首次出现顺序重新编号**
  - 第一个出现的引用 → [1]
  - 第二个出现的引用 → [2]
  - 依此类推
- 同步更新文末参考文献列表的顺序，使其与正文新编号一致
- 如果同一文献被多次引用（多个位置出现），保留首次编号，后续使用同一编号

**术语修正策略：**
- 以术语首次出现时的写法为准（通常摘要或第一章最规范）
- 将后续变体替换为推荐写法
- **例外**：如果变体出现在"概念辨析"或"文献综述"中，且有明确的目的（如对比不同学者的叫法），不要修改

**执行方式：**
- 逐章读取原文件 → 在内存中修正 → 写出修正后的章节到 `_state/chapterX_fixed.md`
- 修正时参考 `_state/reference_index.md` 和 `_state/term_glossary.md`

### 阶段五：合并输出

1. **合并修正后的章节**：按顺序合并所有 `_state/chapterX_fixed.md`
2. **更新文末参考文献**：根据新编号重新排列参考文献列表
3. **生成修改报告**：基于 `_state/changes_log.md` 生成用户可读的报告

**输出文件：**
- `<原文件名>_修正版.md`：修正后的完整论文
- `<原文件名>_修改报告.md`：详细的修改说明

## 修改报告格式

```markdown
# 论文修改报告

## 一、参考文献引用修正

### 1.1 编号重新排序（共 X 处）
| 原编号 | 新编号 | 所在章节 | 文献 |
|--------|--------|----------|------|
| [15] | [12] | 第3章 | AJZEN I... |
| [3] | [2] | 第2章 | BANDURA A... |

### 1.2 重复引用合并（共 X 处）
| 保留编号 | 合并编号 | 所在章节 |
|----------|----------|----------|
| [5] | [5], [23] → 均改为 [5] | 第2章, 第6章 |

### 1.3 缺失引用补充（共 X 处）
正文中引用 [X] 在参考文献列表中找不到对应条目，已补充。

## 二、术语一致性修正

### 2.1 统一术语（共 X 处）
| 推荐写法 | 被替换的变体 | 所在章节 | 替换次数 |
|----------|-------------|----------|----------|
| 体育虚拟社区 | 虚拟体育社区 | 第3章 | 3 |
| 持续运动行为 | 持续性运动行为 | 第2,5章 | 5 |

### 2.2 疑似不一致（建议人工确认）
| 术语 | 变体 | 所在章节 | 说明 |
|------|------|----------|------|
| 心流体验 | 福流 | 第4章 | 可能是台湾译法，请确认是否保留 |

## 三、其他问题
（如格式不统一、标点问题等）
```

## 重要原则

1. **不要修改原文的学术内容**：只修正编号和术语，不改变论点、数据或分析
2. **保守替换术语**：如果变体可能是故意的（如引用不同学者的不同表述），放入"疑似不一致"区域，让用户确认
3. **保留原始文件**：始终生成新文件，不要覆盖用户原文件
4. **状态文件可复用**：`_state/` 目录保留，用户下次修改同一论文时可直接增量更新
5. **分批处理**：如果论文章节超过 8 章，每处理 2-3 章后更新一次状态文件，避免上下文过长

## 边界情况处理

| 情况 | 处理方式 |
|------|----------|
| 论文中没有 `[数字]` 引用（纯作者-年份制，如 `（张三, 2020）`） | 仅检查术语一致性，跳过引用编号修正 |
| 混合格式（既有 `[数字]` 又有 `（作者, 年份）`） | 修正 `[数字]` 格式部分，记录混合格式位置提醒用户 |
| 文末无参考文献列表 | 报告缺失，建议用户补充 |
| 用户只给了一章 | 只处理该章，生成部分索引，提醒用户完整论文需全章处理 |
| 分文件输入且文件名无序 | 先读取所有文件，按内容中的章节号排序处理 |

## 示例：与用户交互流程

**用户输入：**
"帮我检查一下 `论文初稿_完整版.md`，参考文献编号好像乱了，术语也不统一。"

**Skill 执行：**
1. 检查文件大小（如 257KB）→ 判断需要分块处理
2. 执行预分析（bash）→ 发现 8 章 + 参考文献，2147 行
3. 逐章扫描 → 生成 `_state/reference_index.md` 和 `_state/term_glossary.md`
4. 全局检查 → 发现 3 处编号顺序错误，5 处术语变体
5. 逐章修正 → 生成 `_state/chapterX_fixed.md`
6. 合并输出 → 生成 `论文初稿_完整版_修正版.md` + `论文初稿_完整版_修改报告.md`
7. 向用户汇报修改概况，提供报告摘要
