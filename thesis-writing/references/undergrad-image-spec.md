# 图片处理规范

## 基本格式

论文中所有图片均使用文字占位符，格式如下：

```
> [图X-Y 图片标题]
> 描述：详细描述图片应展示的内容
```

- X 为章节号，Y 为章内顺序号
- 编号全章连续，不得跳缺或重复
- 图片标题应简洁准确，反映图片核心内容

## 各类型图片描述要求

### 用例图
- 明确标注中心角色名称
- 逐一列出该角色的所有用例（功能操作）
- 说明用例之间的关系（如包含、扩展）

示例：
```
> [图2-1 用户用例图]
> 描述：中心角色为"用户"，用例包括：注册账号、登录系统、浏览商品列表、
> 搜索商品、发布闲置商品、编辑商品信息、删除商品、购买商品、查看订单、
> 管理收货地址、管理个人信息；每个用例用椭圆表示，角色与用例之间用连线关联
```

### 系统技术架构图
- 按分层结构从上到下描述每一层
- 每层标注层名称、包含的技术组件
- 说明层与层之间的交互方式
- 标注辅助组件的位置

示例：
```
> [图3-1 系统技术架构图]
> 描述：分层架构图，从上到下依次为：
> 表现层（浏览器 + Vue 2.x前端页面，使用Element UI组件库）→
> 控制层（SpringBoot Controller，处理HTTP请求，RESTful API接口）→
> 业务逻辑层（Service层，处理用户认证、商品管理、订单处理等核心业务）→
> 数据访问层（MyBatis，负责SQL映射和数据库操作）→
> 数据存储层（MySQL 5.7数据库，存储用户、商品、订单等数据）；
> 右侧标注辅助组件：Maven构建工具、内嵌Tomcat服务器、Swagger API文档
```

### 系统功能结构图
- 采用树状层级结构描述
- 顶层为系统名称
- 第二层为子系统划分（如前台、后台）
- 第三层为功能模块
- 第四层为具体功能点（如有）
- 所有模块和子模块必须逐一列出，不得省略

示例：
```
> [图3-2 系统功能结构图]
> 描述：树状结构图，顶层为"闲置物品交易系统"；
> 第二层分为"前台用户子系统"和"后台管理子系统"；
> 前台用户子系统包含：注册登录（注册、登录、找回密码）、
> 商品浏览（商品列表、商品详情、商品搜索）、
> 商品管理（发布商品、编辑商品、删除商品、上下架）、
> 订单管理（下单、查看订单、确认收货）、
> 个人中心（个人信息、收藏管理、收货地址）；
> 后台管理子系统包含：用户管理（查看、禁用、删除）、
> 商品管理（审核、编辑、删除）、
> 订单管理（查看、处理）、
> 分类管理（增删改查）、
> 公告管理（发布、编辑、删除）、
> 数据统计（用户统计、交易统计）
```

### 流程图
- 必须有明确的起点和终点
- 每个步骤用动词开头描述
- 判断分支必须标注"是/否"走向
- 完整描述从发起到结束的每一步骤，不得省略

示例：
```
> [图3-3 用户登录流程图]
> 描述：起点→用户打开登录页面→输入用户名和密码→点击登录按钮→
> 系统验证用户名是否存在→若不存在则提示"用户名不存在"并返回登录页→
> 若存在则验证密码是否正确→若密码错误则提示"密码错误"并返回登录页→
> 若密码正确则判断用户角色→若为普通用户则跳转用户首页→
> 若为管理员则跳转后台管理首页→结束
```

### E-R 图（实体关系图）
- 明确标注实体名称
- 逐一列出该实体的所有属性字段
- 说明与其他实体的关联关系
- 标注关联类型（一对一、一对多、多对多）

示例：
```
> [图3-6 用户实体E-R图]
> 描述：展示"用户"实体的所有属性字段：用户ID（主键）、用户名、密码、
> 手机号、头像、注册时间、状态；
> 与"商品"实体为一对多关系（一个用户可发布多个商品）；
> 与"订单"实体为一对多关系（一个用户可有多个订单）；
> 与"收藏"实体为一对多关系（一个用户可收藏多个商品）
```

### 界面截图
- 说明页面名称和所属模块
- 列出页面包含的主要UI元素
- 描述页面的布局结构
- 说明主要交互功能

示例：
```
> [图4-3 商品列表页面截图]
> 描述：展示前台商品列表页面，页面布局为：顶部导航栏（含Logo、搜索框、
> 用户头像下拉菜单）、左侧商品分类筛选栏、右侧主内容区以卡片形式展示
> 商品（每张卡片包含商品图片、标题、价格、发布者、发布时间）、
> 底部分页组件支持翻页浏览
```
