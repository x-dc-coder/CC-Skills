## 3 系统设计

### 3.1 设计方案

本系统采用 B/S（Browser/Server）架构模式进行设计与开发。前端使用 Vue.js 框架构建用户界面，通过 Axios 发起 HTTP 请求与后端进行数据交互；后端基于 SpringBoot 框架搭建 RESTful API 服务，使用 MyBatis 作为持久层框架操作 MySQL 数据库。系统整体遵循 MVC 设计模式，实现了前后端分离的开发方式，降低了模块间的耦合度，提高了系统的可维护性和可扩展性。

在安全性方面，系统采用 JWT（JSON Web Token）进行用户身份认证，通过拦截器对需要登录才能访问的接口进行权限校验。密码存储采用 BCrypt 加密算法，防止明文泄露。

### 3.2 总体设计

#### 3.2.1 系统技术架构设计

系统采用分层架构，各层职责明确，层与层之间通过接口进行通信。整体技术架构如图3-1所示。

> [图3-1 系统技术架构图]
> 描述：分层架构图，从上到下依次为：
> 表现层（浏览器 + Vue 2.6 前端页面，使用 Element UI 组件库构建界面）→
> 控制层（SpringBoot Controller，提供 RESTful API 接口，处理 HTTP 请求和响应）→
> 业务逻辑层（Service 层，处理用户注册登录认证、商品发布与管理、订单创建与处理、收藏管理等核心业务逻辑）→
> 数据访问层（MyBatis，负责 SQL 映射和数据库 CRUD 操作）→
> 数据存储层（MySQL 5.7 数据库，存储用户信息、商品信息、订单信息、分类信息等数据）；
> 右侧标注辅助组件：Maven 项目构建工具、内嵌 Tomcat 服务器、Swagger API 文档工具

表现层负责用户界面的展示和交互，通过 Vue Router 实现页面路由管理，使用 Vuex 进行全局状态管理。控制层接收前端发送的 HTTP 请求，进行参数校验后调用业务逻辑层的服务方法。业务逻辑层封装了系统的核心业务处理流程，是系统功能实现的关键。数据访问层通过 MyBatis 的 Mapper 接口与 XML 映射文件，完成对数据库的增删改查操作。

### 3.3 系统执行流程

#### 3.3.1 用户登录流程

用户登录是系统的基础功能，登录流程如图3-3所示。

> [图3-3 用户登录流程图]
> 描述：起点→用户打开登录页面→输入用户名和密码→点击登录按钮→
> 系统验证用户名是否存在→若不存在则提示"用户名不存在"并返回登录页→
> 若存在则验证密码是否正确（BCrypt 解密比对）→
> 若密码错误则提示"密码错误，请重新输入"并返回登录页→
> 若密码正确则检查用户状态是否正常→若被禁用则提示"账号已被禁用"→
> 若正常则生成 JWT Token 并存入浏览器 LocalStorage→
> 判断用户角色：若为普通用户则跳转前台用户首页→
> 若为管理员则跳转后台管理首页→结束

用户在登录页面输入用户名和密码后，系统首先查询数据库验证用户名是否存在，然后通过 BCrypt 算法比对密码是否正确。验证通过后，系统生成包含用户信息的 JWT Token 返回给前端，前端将 Token 存储在 LocalStorage 中，后续请求在 Header 中携带该 Token 进行身份认证。

#### 3.3.2 商品发布流程

商品发布是用户的核心操作之一，发布流程如图3-4所示。

> [图3-4 商品发布流程图]
> 描述：起点→用户点击"发布商品"按钮→系统检查用户是否已登录→
> 若未登录则跳转登录页面→若已登录则展示商品发布表单→
> 用户填写商品信息（标题、描述、价格、分类、上传图片）→点击提交→
> 前端校验表单数据是否完整→若不完整则提示补充必填项→
> 若完整则将数据发送至后端 API→后端校验数据合法性→
> 若不合法则返回错误信息→若合法则将商品信息写入数据库→
> 返回发布成功提示→跳转至商品详情页→结束

根据需求分析，本系统涉及的核心实体包括用户、商品、订单、分类和收藏。各实体的 E-R 图如下。

> [图3-6 用户实体E-R图]
> 描述：展示"用户"实体的所有属性字段：用户ID（主键）、用户名、密码、
> 昵称、手机号、头像URL、角色（普通用户/管理员）、状态（正常/禁用）、

> 与"商品"实体为一对多关系（一个用户可发布多个商品）；
> 与"订单"实体为一对多关系（一个用户可创建多个订单）；
> 与"收藏"实体为一对多关系（一个用户可收藏多个商品）

> [图3-7 商品实体E-R图]

> 与"用户"实体为多对一关系（多个商品属于一个用户）；
> 与"分类"实体为多对一关系（多个商品属于一个分类）；

> 买家ID（外键）、商品ID（外键）、订单金额、订单状态（待付款/已付款/已发货/已完成/已取消）、
> 收货地址、联系电话、创建时间、更新时间；
> 与"用户"实体为多对一关系（多个订单属于一个买家）；
> 与"商品"实体为一对一关系（一个订单对应一个商品）
